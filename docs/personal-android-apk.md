# 咲咲的安卓安装包

应用名称：SullyOS·糯米机。独立包名：`com.kke7777.nuomi`，可与原作者的安装包并存。
保留当前首页布局、图标名称、独立日程页和聊天提示词；安卓系统状态栏显示在透明背景上，
首页壁纸与各页面顶栏背景自然延伸到时间、电量、信号下方。应用内的模拟时间/电量条继续隐藏。

## 系统状态栏融合

`NativeSystemBars` 原生插件负责透明状态栏、显示系统图标，以及系统栏/屏幕挖孔/键盘的实际安全区。
顶部高度按设备像素密度转为 CSS 像素，接入已有 `--safe-top`；背景保持铺满，标题与按钮让位一次。
底部导航栏、键盘和横屏侧边挖孔由原生容器留位，WebView 不再重复消费这些 insets。
Keyboard 插件仍提供键盘事件；其旧全屏手动改高度逻辑关闭，避免与原生避让重复。

页面顶边的底色/壁纸代表色用于选择深色或浅色系统图标。复用现有 iOS 取色逻辑，
按页面切换、样式变更、加载和前后台事件更新，不常驻轮询，不监听聊天正文流。
取色仅影响图标明暗，Android 背景仍是页面实际绘制；跨域图片无 CORS 时用 CSS 底色估算，
复杂渐变或高反差壁纸需在手机上确认图标可读性。浏览器和 iOS 不启用此原生插件。

## 原生推送

Android 原生插件 `AmsgUnifiedPush` 使用官方 UnifiedPush connector 3.3.5，支持加密 Web Push。
本 APK 不接入 Firebase / FCM，不需要 google-services.json 或 Firebase 项目。
官方连接器负责分发服务选择、订阅、发送者校验与解密；糯米机插件负责本机收件箱、分片重组、
系统通知、通知点击及与网页聊天数据库的交接。分片协议与仓库当前 `@rei-standard/amsg-shared` 一致。

手机上还需要一个 UnifiedPush 分发服务。按现有代码默认引导，使用 ntfy 的无 Firebase 版本。
它维持服务器连接，糯米机的 receiver/service 接收消息，因此不需要一直打开糯米机界面。
这不能绕过安卓的「强行停止」或厂商的后台限制；系统实际送达需要手机和用户 Worker 联调。

1. 安装并打开 ntfy 的无 Firebase 版本，确认其推送服务器在手机网络上可访问。
2. 允许 ntfy 后台运行，并允许糯米机显示通知。
3. 在糯米机的主动消息设置中填写并验证自己的 Worker 地址，再开启通知与推送订阅。
4. 在应用内发送测试通知，再回桌面或锁屏测试；点击通知应打开对应角色聊天。

消息先保存到本机 SQLite，再交给现有聊天管线。网页入库成功才确认删除本机待处理行，失败则保留，
启动或回前台时重试。长消息支持乱序、重复分片与 UTF-8 重组；普通正文、情绪、后台任务结果和失败事件
按各自管线处理。订阅地址变动时重新登记到当前用户 Worker。不同通知各自携带正确的点击目标。

## 构建与升级

安装 Node、pnpm、JDK 17、Android SDK 34 / Build Tools 34.0.0，设置 `ANDROID_HOME`。

```sh
pnpm install --frozen-lockfile
pnpm build:android
```

默认生成已签名开发包。正式版提供环境变量后运行相同命令：

- `NUOMI_KEYSTORE`：个人签名文件的绝对路径。
- `NUOMI_STORE_PASSWORD`：签名文件密码。
- `NUOMI_KEY_ALIAS`：密钥名称。
- `NUOMI_KEY_PASSWORD`：密钥密码。

本次版本的 Android versionCode 为 16（1.6.7-timeout1018）。副 API 整理等待上限延长至 120 秒，提前完成立即继续主回复；失败时继续使用完整召回原记忆兜底，超时提示明确说明采用了原记忆。副 API 回忆写作任务按编号说明资料作用与要求，目标长度 1000–1600 字，只忠实整理已有回忆，不补写未发生的事情，也不提供下一步回复建议。副 API 参考的当前聊天原文最多保留水位线后最近 60 个可见气泡，主聊天模型的上下文范围与世界书触发范围不变。
主聊天 API 调用记录按实际注入来源归类，人设正文中的小标题不再拆成独立统计项，完整保留主聊天各来源分类；旧记录已合并的部分会提示无法还原。精简副 API 参考资料的重复包装字段，保留全部正文、来源、顺序及独立写作任务。包含聊天召回后二次加工、最近使用回忆查看页，并删除普通聊天规则的“2.5 对话质量”整节；保留已有生图、相册、语音与推送功能。沿用原包的包名与签名，可以覆盖安装。
副 API 使用独立的回忆写作任务，人设与聊天作为参考资料，省略通用模板的“暂无特定记忆，请基于当前对话互动”。返回明显聊天记录或固定记忆模板时，保留错误原文并使用完整召回材料。页面分别显示副 API 原始返回、采用的回忆正文和完整注入内容。本次修复不需要更新 Worker。
记忆宫殿选角页的角色卡片可直接打开“最近使用的回忆”，角色房间、像素家园和角色设置页也提供入口。副 API 输入构成及完整请求查看将“本次召回记忆”单独列出，保留实际发送的完整召回批次；旧调用记录的历史统计不变。
聊天头像旁保留三点动画，并按实际生成阶段显示“露易丝在回忆ing”或“露露打字ing”；召回与副 API 整理共用回忆阶段，主请求发出后切换打字，结束或停止时收起。其他角色沿用各自名称。
后续覆盖升级须使用同一签名并递增 versionCode。签名文件和密码不提交到仓库。
本 APK 没有原作者的 ApkInstaller 插件，因此不接入原作者 APK 自动更新地址；更新包可手动覆盖安装。

上一版已替换主动消息 2.0 的自主联系说明和排程限制文案，保留用户名、剩余额度、间隔、
任务名额及循环／必发开关的动态生成。云端共用文案的 Worker 版本为 `2026-10-13.1`；
如尚未升级到这个 Worker 版本，在主动消息 2.0 设置里复制新版 Worker 代码，更新原有 Cloudflare Worker。
本次状态栏修改不需要更新 Worker。
本地聊天使用安装包内的新文案；即时对话和到点生成使用更新后的云端文案。

## 从相册添加表情包

聊天 → 笑脸表情面板 → 选好分类 → 列表里的「＋」→「从相册选择」。
选择一张图片，确认预览、填写能描述画面或情绪的名称，再点「添加至当前分类」。
保留原有「链接导入」入口。图片原文件存入本机图片库，不上传图床，不压缩为静态图，
GIF 动图保留原始字节；无法预览的图片不能保存。同名表情会提示改名，不覆盖已有图片。

添加成功后刷新表情面板，并标记主动消息表情清单需要同步。AI 仍按表情名称选择图片，
沿用分类的「设置可见角色」规则；无需给人设另加提示词。换设备时应使用完整备份迁移。
本功能需要安装包含该代码的新 APK；已安装的旧 APK 不会因仓库更新而自动增加入口，
不需要因此更新 Cloudflare Worker。

验证：`pnpm vitest run utils/emojiImport.test.ts utils/emojiImportDialog.test.ts`。

网页版、原版 APK 与此独立 APK 各自保存数据。首次迁移在原应用「备份与恢复」导出，
再在本 APK 导入。联网对话和语音继续使用用户自行填写的 API。

构建与自动化模拟测试不等同于真机端到端验收。录音、键盘、分享和实际后台推送需在手机上确认。

参考：https://unifiedpush.org/kdoc/connector/ 、https://unifiedpush.org/developers/spec/android/

## 聊天生图版本

包含 2026-10-16 的异地聊天提示词、四节版生图指南和默认日系二次元动漫风格。
使用方式及前台执行说明见 [聊天生图](image-generation.md)。保留相册表情、系统状态栏、语音和原生推送。
安装后在「设置 → 生图 API」保存接口与人物参考图，在聊天功能面板开启当前会话生图。
生图开关默认关闭；本功能不要求更新 Cloudflare Worker。
